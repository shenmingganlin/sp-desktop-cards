# SP 桌面卡片

> 以前叫「SP 今日小窗」。功能早就不只管今天了，0.2.3 起改叫「SP 桌面卡片」。

[Super Productivity](https://super-productivity.com/)（SP）的桌面卡片。每个功能一张卡片，想看哪张开哪张，卡片之间可以拼接吸附，拼好的一组一起拖动。

| 卡片 | 内容 |
| --- | --- |
| **专注** | 当前在计时的任务和剩余时间；自带番茄钟（专注时让 SP 给当前任务计时，休息时停）；SP 自己的专注模式在跑时显示它的倒计时 |
| **今日** | 逾期、今日、已完成三组，和 SP 今日视图一致；勾选完成（可撤销）、开始/停止计时；顶栏「+」快速新建 |
| **规划** | 从今天起几天，每天的任务、还没生成的重复任务、截止日、剩余预估；每天都能直接新建 |
| **日程** | 某一天的时间轴，按时间和预估画成块，重叠的并排；点空白处在那个时间新建；可以翻到前后几天 |
| **月历** | 一个月的网格，圆点表示那天有待办，红点是截止日；点一天看那天的内容并在那天新建 |
| **统计** | 今天用了多久、完成几项、几个番茄；最近 7 天每天的用时画成柱状图，今天用强调色；底下一行是 7 天合计和日均 |
| **清单** | 某个项目或某个标签下的全部任务。顶栏按钮切换看哪个；有截止日的排前面，子任务挂在父任务下面；能勾选、能计时 |
| **热力图** | 最近 13 周每天一个格子，颜色越深那天用得越久，像 GitHub 的贡献图；鼠标停上去看当天用时和完成数 |
| **待整理** | 散在各处、还没归位的东西分三堆：收件箱、没排期、没收尾。每行能直接计时；前两堆能「排到今天」，没收尾能直接「完成」 |
| **时间去向** | 最近 7 天的时间按标签或项目分摊，横条从大到小。一条任务挂多个标签时每个标签各算一次，卡片会写明合计比实际多 |

## 摆放

- **拖动**：按住顶栏拖。靠近别的卡片或屏幕边缘时会吸过去，拼在一起的卡片之后整组一起走；按住 **Alt** 拖只挪这一张。
- **改大小**：拖卡片边缘（四边和四个角都行，有八个把手）。拉到和别的卡片边缘共线、或者挨着拼起来的位置时会吸一下，方便对齐；按住 **Alt** 拖就不吸。拼在旁边的卡片会跟着让开或靠拢。
- **折叠**：双击顶栏或点左边的 ▾，收成一行，下面拼着的卡片跟上来。
- **显示方式**（顶栏 ⋯ 菜单、托盘菜单或设置里切换）：
  - 置顶：浮在所有窗口上面。
  - 普通窗口：和其他窗口一样，会被盖住。
  - 嵌入桌面：贴在桌面图标那一层，按 Win+D 显示桌面时卡片还在；平时被其他窗口盖住。
    桌面模式下卡片全程不抢激活：点桌面、开卡片菜单、打字，卡片本身都留在那一层不动（菜单自己浮在上面）。
- **锁定位置**：防止误拖。
- **不挡点击**：打开后鼠标落在卡片上会穿透到下面——置顶时点到卡片底下的程序，嵌入桌面时点到桌面图标和壁纸。默认关。按快捷键（默认 `Ctrl + Alt + J`）随时切换，桌面下方会浮一条提示告诉你开还是关。快捷键可以在设置 → 显示里点「设置快捷键…」改：弹出的窗口画着一个键盘，左键点选、右键取消，Ctrl / Alt / Shift / Win 可以多选，普通键只能选一个。组合被别的程序占用时会当场提示，原来的不动。三个入口都能切：快捷键、托盘菜单、卡片 ⋯ 菜单。
- 托盘图标：单击显示/隐藏全部卡片，右键有完整菜单。

## 皮肤

设置 → 外观，选「选择…」打开皮肤窗口。皮肤不占设置页的地方，一共 12 套：

- **深夜**：默认，深灰底 + 玫红强调，和以前的版本一模一样。
- **Hana 的 11 套主题**：暖纸、青夜、素白、草香、沉思、Absolutely、随时准备接住你、用户彻底怒了、新暖纸、青夜·高对比、珊瑚。颜色、圆角、细边、标题字体都跟 Hana 一致。

换皮肤即时生效，不用重启；卡片、设置、教程、更新窗口一起换。

如果本机装了「任务台」这个 Hana 应用，它可以在你允许后让卡片跟着 Hana 当前主题走：Hana 用哪套，卡片就用同一套。小窗只认 `%APPDATA%\SP 桌面卡片\theme.json` 这个通用外部主题文件，也可以由别的程序来写；文件里的 `theme` 就是上面某个皮肤 id。外部文件存在且合法时压过设置里手选的皮肤，删掉就回到手选。0.3.0 的旧名字 `hana` 仍然认，等于「新暖纸」。

## 番茄钟

在「专注」卡片点 ▶ 专注开始。SP 正在给某个任务计时的话，番茄钟和它一起走：专注时让 SP 计时，休息时停。

一个阶段结束时：

- 卡片自己放提示音。系统通知在勿扰、专注助手打开时不响，提示音不受影响。
- 系统通知一直留着，点掉或开始下一阶段才消失。
- 「专注」卡片浮到所有窗口上面并闪几下，点一下或开始下一阶段后回到原来的位置。

托盘图标上悬停能看到剩余时间。设置里可以关掉提示音或浮到最前，也可以打开「退出或重启后接着走」和「结束番茄前确认」（这两项默认关）。

第一次启动会弹出使用教程，之后在顶栏 ⋯ 菜单或托盘菜单里点「使用教程」再看。

新建任务时可以用 SP 的简写（`#标签`、`+项目` 等），由 SP 解析。新任务默认进收件箱，可以在设置里换成别的项目。

## 更新

启动时一天最多自动查一次有没有新版本（设置 → 关于 里可以关）。发现新版本会先问，不会偷偷装：

- **安装版**：点「下载并安装」，下完提示你安装；装的时候小窗先退出，装好自己回来，设置和卡片位置都保留。
- **免安装版**：给一个下载页链接，自己解压替换。

也可以随时在 ⋯ 菜单或设置里点「检查更新…」。不想被某个版本打扰，点「跳过这个版本」。

检查更新只读本仓库 Releases 页面的跳转（`github.com/<仓库>/releases/latest`），不发任何本机数据。不用 `api.github.com`：没登录的接口每个 IP 每小时只有 60 次，共享出口常被用光。

## 使用前提

1. SP 桌面版 19.3 或更新，并且正在运行。
2. 在 SP「设置 → 杂项」里打开**本地 REST API**。打开后 SP 会生成访问令牌，小窗会自动读取，不用复制粘贴。读不到时可以在设置里手填，手填的令牌用系统加密保存。

任务数据只连本机的 `127.0.0.1:3876`。唯一联网的地方是检查更新，只请求 GitHub 上本仓库的 Release 列表。

## 从 0.1.0 升级

直接安装新版。原来的窗口位置给「今日」卡片，「专注」卡片拼在它上方；其他设置保留。规划、日程、月历默认不显示，在顶栏 ⋯ →「卡片」里打开。

## 已知限制

- 目前只在 Windows 11 上测试过。「嵌入桌面」只在 Windows 上有。
- 安装包没有代码签名，第一次运行时 Windows SmartScreen 会提示「未知发布者」，点「更多信息 → 仍要运行」。
- SP 的 REST API 不会推送变化，小窗每 2 秒查一次当前计时，每 15 秒查一次任务列表。在 SP 里改了任务，小窗最多 15 秒后更新。
- REST API 只能读 SP 自己的专注模式，不能控制，所以番茄钟是小窗自带的。SP 的专注模式在跑时，暂停/继续请在 SP 里操作。
- 日历事件（Google 日历、CalDAV 插件的数据）读不到，REST API 不提供。
- 日程卡片不会像 SP 那样把没定时间的任务自动排进空档，它们放在时间轴上方。
- **启动后立刻退出、没有窗口**：Electron 45 启动时会检查安装目录的权限。如果目录的权限表里有某个应用沙盒（AppContainer）的专属条目，却没有「所有应用程序包」，就会拒绝启动。装过 Codex 等带沙盒的软件后，`%LOCALAPPDATA%\Programs` 和 `%TEMP%` 可能是这种状态。解决办法二选一：
  - 安装时换一个目录（例如 `D:\Apps\SP 桌面卡片`），或用 zip 版解压到别的盘；
  - 给安装目录补上权限（把路径换成你的安装目录）：`icacls "安装目录" /grant *S-1-15-2-1:(OI)(CI)(RX)`

## 下载

在 [Releases](https://github.com/shenmingganlin/sp-desktop-cards/releases/latest) 页面下载：

- `sp-desktop-cards-<版本>-setup.exe`：安装版，可选安装目录，带开始菜单和桌面快捷方式。
- `sp-desktop-cards-<版本>-win-x64.zip`：免安装版，解压后运行 `SP-Desktop-Cards.exe`。

## 开发

```bash
npm install
npm start               # 运行
npm test                # 单元测试：数据整理、重复任务、吸附、番茄钟、设置迁移、客户端
npm run smoke           # 用假 SP 启动真实窗口，每张卡片截图，输出到 .smoke/
npm run ui-check        # 用 Playwright 点一遍：勾选、计时、番茄钟、新建、翻页、折叠、拖动、设置、断线
npm run menu-check      # 嵌入桌面模式：菜单/点别处/连点/Win+D/外力抬起，卡片都留在桌面层不动
npm run desktop-check   # 嵌入桌面模式真机检查（会按 Win+D、移动鼠标，运行时别碰电脑）
npm run destroy-check   # 窗口被系统销毁时主进程不崩，卡片能自己重建
npm run clickthrough-check # 不挡点击：真的穿透到下面，子窗口显示回来也不影响
npm run hotkey-check    # 不挡点击的整条链路：快捷键、切换、提示条、录制窗、占用冲突
npm run update-check    # 检查更新：手动那条（发现→下载→问要不要装）+ 启动后自动弹窗那条（真弹原生对话框）
npm run dist            # 打 Windows 安装包和 zip，输出到 dist/
```

检查脚本只连假 SP。设 `SPW_EXE` 指向打包好的 `SP-Desktop-Cards.exe` 时，smoke 和 desktop-check 检查打包产物。

代码结构：

- `src/main/model.js`：今日卡片的数据整理（纯函数）
- `src/main/calendar.js`：规划、日程、月历的数据整理（纯函数）
- `src/main/list.js`、`heatmap.js`、`triage.js`、`breakdown.js`：清单、热力图、待整理、时间去向的数据整理（纯函数）
- `src/main/repeat.js`：SP 判断「某天有没有这个重复任务」的规则，从 SP 源码移植，用 SP 自己的测试核对（`test/sp-spec/`）
- `src/main/cards.js`：卡片窗口：摆放、拖动、吸附、折叠联动、三种显示方式
- `src/main/snap.js`：吸附和拼接的几何计算（纯函数）
- `src/main/desktop.js`：嵌入桌面（用 koffi 调 user32、comctl32）
- `src/main/pomodoro.js`：番茄钟状态机（纯函数）
- `src/main/sp-client.js`、`poller.js`：REST 客户端和轮询。SP 会拒绝带网页 Origin 的请求，所以请求都由主进程发出
- `src/main/hotkey.js`：快捷键的规范化、校验、转 Electron accelerator（纯函数）
- `src/main/win.js`：窗口判活（原生窗口被系统销毁时 `isDestroyed()` 还来不及置上）
- `src/main/main.js`：托盘、菜单、设置窗口，把以上串起来
- `src/renderer/`：卡片页面（`card.js` 共用部分，`cards/` 每张卡片一个文件）、设置窗口、使用教程（`tour.*`）、提示音（`chime.js`）
- `test/fake-sp.js`：照 SP 19.3 行为写的假服务，测试和截图都用它
